1. Project Overview
The "Employee Payroll Management System" project (J1.L.P0037) is a console-based application developed in Java following the Object-Oriented Programming (OOP) approach. It manages employee information and calculates the monthly payroll. The system also includes a role-based authorization layer: users must log in, and each role (Admin or Staff) is granted access to a specific set of functions. Employee records are stored in a text file (employees.txt), and the system supports loading, adding, updating, removing, searching, payroll calculation, displaying and saving data safely.
In addition to payroll, the system provides a Meal Allowance (Phu cap an) sub-module (Feature 9): a separate CRUD menu that manages per-employee monthly meal allowances, stored in its own data file (meal_allowances.txt). The main menu therefore now offers 10 features (Quit is Feature 10).

4.2. Factory Layer
EmployeeFactory.java
Centralizes object creation: maps a role string to the correct Employee subclass. Adding a new role only requires one new subclass and one factory branch (Open/Closed Principle).

6. Feature Usage Guide
6.0. Login & Authorization
On startup, enter a username and password. After 3 failed attempts the program exits. Once logged in, the menu shows all 10 features but marks the ones outside your role as [locked]; selecting a locked feature shows "Access denied".

6.1. Feature 1: Load employee data from file
Enter 1 -> Reads employees.txt line by line. Invalid lines (wrong field count, bad number, failed validation, or duplicate ID) are skipped safely and counted. Example: "Loaded 11 record(s), skipped 3 invalid line(s)."

6.2. Feature 2: Add a new employee (Admin only)
Enter 2 -> Input the following fields (each validated; invalid input is re-prompted):
Employee ID (Exxx) - format validated, duplicates rejected
Name - non-empty
Role - Developer/Tester/Manager/HR
Base salary - must be positive
Working days - 0 to 26
Bonus - >= 0
Status - active/inactive
If all fields are valid -> "Employee added successfully."

6.3. Feature 3: Update employee information (Admin only)
Enter 3 -> Input Employee ID -> Update role, salary, working days, bonus, status. Press Enter to keep the current value. Changing the role re-creates the object as the correct subclass via the factory.
6.4. Feature 4: Remove an employee by ID (Admin only)
Enter 4 -> Input Employee ID -> Confirm (Y/N). Employee removed, or "This employee does not exist!" / "Cancelled.".
6.5. Feature 5: Search employees by attribute
Enter 5 -> Choose attribute (1.ID 2.Name 3.Role 4.Status) -> Input keyword -> Displays all matching employees (case-insensitive substring match).

6.6. Feature 6: Calculate monthly payroll
Enter 6 -> Displays each active employee with their computed salary (polymorphic calculateSalary()), then the TOTAL payroll. Inactive employees are skipped.

6.7. Feature 7: Display employee list
Enter 7 -> Displays all employees in a formatted table (ID | Name | Role | Base | Day | Bonus | Status | Salary).

6.8. Feature 8: Save data to file (Admin only)
Enter 8 -> Writes all employees back to employees.txt in the 7-field format. Example: "Data saved to 'employees.txt' (N record(s))."

6.9. Feature 9: Meal allowance management (Phu cap an)
Enter 9 -> Opens the Meal Allowance sub-menu. The module first loads meal_allowances.txt, shows the unit price (30,000 / day), then loops its own 6-option menu:
Create meal allowance - input id (ML-xxxx), employee id (must exist), month (MM/yyyy) and days (0-26); duplicates are rejected and the computed amount is shown.
Read - print all records in a table (ID | EmpID | Month | Day | Amount).
Update days - input id, then new days; the amount is recalculated automatically.
Delete by id - input id, then confirm (Y/N).
Save to file - write all records to meal_allowances.txt.
Back to main menu - prompts to save if there are unsaved changes.

6.10. Feature 10: Quit program
Enter 10 -> If unsaved changes are detected (dirty flag), prompts "Save before exit? (Y/N)". Then exits with "Goodbye!".

8. Conclusion
8.1. Achievements
Implemented all core features for employee management and payroll (Features 1-8, 10).
Added a role-based authorization layer (login + Admin/Staff permissions).
Applied OOP principles to both the employee model and the authorization model.
Strict validation: regex (ID), value ranges, role/status sets, unique ID.
Polymorphic salary calculation and polymorphic access control (no if-else on role).
Monthly payroll counts active employees only.
Safe file loading: malformed lines are skipped and reported, never crashing.
Added a Meal Allowance (Phu cap an) module: its own CRUD sub-menu, ML-id and MM/yyyy validation, composite-key uniqueness (employee + month), amount = days x 30,000, and a check that the linked employee exists.
