Prompt Type        : DECISION-MAKING

Problem / Context  : Topic 31 requires adding a Volunteer entity with id (^VL\d{3}$),
                     name (3..30), skill (enum), maxShiftsPerDay (1..3),
                     shiftsToday. The project already has a Student class extending Person.
                     Question: Should Volunteer be a standalone class, or extend Person
                     like Student?

Prompt to AI       :
"I already have an abstract class Person (id, name) and Student extends Person.
Now I need to add a Volunteer entity with id (VL + 3 digits), name (3-30 chars),
skill (enum MEDIC/LOGISTIC/GUIDE_ASSIST), maxShiftsPerDay (1-3), shiftsToday.
Should Volunteer extend Person or be a standalone class? What about the
Volunteers collection - should it also extend ArrayList like Students?"

AI Response (Summary):
AI suggests: Volunteer should extend Person because they BOTH have id + name, this is a valid IS-A
relationship. Volunteers extends ArrayList<Volunteer> following the same pattern
as Students. AI also advises creating an "Assignable" interface for the assign() method
to abstract the concept of "assigning to a slot".

Human Delta & Reflection:
- Critical Thinking : AI is right about Person inheritance (DRY, reuses id/name).
  BUT suggesting an "Assignable" interface is OVER-ENGINEERING for a 200 LOC project.
  Only Volunteer needs it.
- Contextualization : Existing Person.java works well for Student. Inheriting it
  for Volunteer is natural and saves duplicate code.
- Creative Synthesis: I decided: Volunteer extends Person, Volunteers extends
  ArrayList<Volunteer>. I DID NOT create an Assignable interface to avoid over-engineering.
- Decision Ownership: Chose inheritance to reuse fields and stay consistent
  with Student. Rejected the interface as it's an anti-pattern for a single class.

ENTRY #023
--------------------------------------------------------------------------------
Prompt Type        : PROBLEM-SOLVING
Stage / Component  : Algorithms
Problem / Context  : Topic 31 requires constraint "Do not exceed maxShiftsPerDay":
                     each volunteer has maxShiftsPerDay (1-3), each assign increments
                     shiftsToday by 1, if shiftsToday >= maxShiftsPerDay then
                     DO NOT allow assign anymore. Need a simple + accurate blocking algorithm.

Prompt to AI       :
"My Volunteer has maxShiftsPerDay (1-3) and shiftsToday (counter). When assigning
to a shift, I must check shiftsToday < maxShiftsPerDay before incrementing.
Should I use a try-catch with custom OverShiftException, or a simple boolean
return from assign()? Also, when should shiftsToday be reset to 0?"

AI Response (Summary):
AI suggests 2 approaches:
  (1) Boolean return: assign() returns false if max reached. Caller checks return.
  (2) Custom exception: throw OverShiftLimitException(). Caller try-catch.
AI advises using (2) because "exceptions make the contract explicit and are the
standard pattern in enterprise Java". For reset, AI says: "Use a ScheduledExecutor
to reset shiftsToday at midnight automatically."

Human Delta & Reflection:
- Critical Thinking : AI suggests custom exceptions and ScheduledExecutor.
  This is OVER-ENGINEERING for a console app and unnecessary.
- Contextualization : The requirement just needs a simple block if shifts
  exceed the limit. A simple boolean check is enough.
- Creative Synthesis: I implemented a simple `boolean assign()` method that checks
  `shiftsToday >= maxShiftsPerDay`. The caller handles the false return to print
  "Over shift limit!".
- Decision Ownership: Chose a simple boolean return (O(1) logic) over exceptions
  to keep code short and appropriate for the project scope.

Evidence           : Volunteer.java lines 47-53 (assign() method);
                     Main.java lines 397-405 (caller logic);
                     Test scenario (following exact requirement):
                       Input: VL001, name="Nguyen Van A", skill=MEDIC, max=2
                       -> Assign shift 1: "Assigned successfully! 1/2" ✓
                       -> Assign shift 2: "Assigned successfully! 2/2" ✓
                       -> Assign shift 3: "Over shift limit! ... max shifts (2)"

                       DOES NOT have valueOfIgnoreCase() method in

                       Skill.valueOf("medic") will throw
                       IllegalArgumentException because constant is "MEDIC".
How Detected         : Read Oracle Javadoc directly:
                       https://docs.oracle.com/javase/17/docs/api/java/lang/Enum.html
                       + tried to compile code Skill.valueOfIgnoreCase("medic")
                       -> compile error "cannot find symbol".
                       Cross-check StackOverflow: "java enum case insensitive
                       valueOf" -> no built-in method, must write custom
                       loop or use stream.
Corrective Action    : Do not use valueOf() or "valueOfIgnoreCase()". Instead
                       use menu index (Skill.getByIndex(int)) for user to
                       choose skill via number, completely avoiding text parsing issue.
                       Wrote custom getByIndex() method with bounds check (Skill.java
                       lines 12-18).
